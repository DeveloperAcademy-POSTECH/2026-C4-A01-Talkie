# Talkie Support Page Design System

이 문서는 Talkie 앱의 시각 언어를 서포트 페이지에 일관되게 적용하기 위한 최소 디자인 시스템이다. 앱 화면의 실제 Asset Catalog와 SwiftUI 구현을 기준으로 작성했다.

## 1. 디자인 원칙

- **차분한 어둠:** 사용자가 불안을 느끼는 순간에도 화면이 시끄럽지 않도록 검정과 짙은 회색을 기본으로 한다.
- **명확한 행동:** 중요한 행동은 Talkie Orange 한 색으로 강조한다.
- **짧고 직접적인 안내:** 기능보다 사용자가 얻는 결과를 먼저 말한다.
- **안전 기능의 한계 공개:** Talkie가 실제 보호나 범죄 예방을 보장하지 않으며, 긴급 상황에서는 112를 이용해야 한다는 점을 숨기지 않는다.

## 2. 색상

| Token | 값 | 용도 |
| --- | --- | --- |
| `--talkie-orange-500` | `#FF5B1B` | 기본 CTA, 링크, 핵심 강조 |
| `--talkie-orange-700` | `#C73217` | 눌림·강한 강조 상태 |
| `--talkie-orange-200` | `#FFBA9F` | 부드러운 배경 강조 |
| `--talkie-grey-900` | `#0F0F0F` | 웹 페이지 기본 배경 |
| `--talkie-grey-800` | `#1E1E1E` | 섹션·카드 배경 |
| `--talkie-grey-700` | `#2D2D2D` | 입력 영역·보조 카드 |
| `--talkie-grey-500` | `#696969` | 낮은 강조 텍스트·경계 |
| `--talkie-grey-300` | `#BEBEBE` | 본문 보조 텍스트 |
| `--talkie-grey-100` | `#F0F0F0` | 제목·기본 텍스트 |
| `--talkie-danger` | `#ED2B35` | 112, 삭제 등 위험 행동 |

오렌지는 한 화면에서 가장 중요한 행동 1개에 우선 사용한다. 위험 행동에는 오렌지 대신 빨강을 사용한다.

## 3. 타이포그래피

- 기본 서체: `Pretendard`, 대체 서체는 `-apple-system`, `BlinkMacSystemFont`, `sans-serif`
- Display: 40/48, Bold — 페이지 핵심 문장
- Heading 1: 32/40, Bold — 문서 제목
- Heading 2: 24/32, SemiBold — 섹션 제목
- Heading 3: 18/26, SemiBold — 카드 제목
- Body: 16/26, Regular — 설명과 도움말
- Caption: 14/21, Regular — 메타 정보와 보조 안내
- Button: 16/24, Bold — 행동 문구

본문은 한 줄 68자를 넘기지 않고, 한국어 문장은 가능하면 2문장 이내로 쪼갠다.

## 4. 레이아웃과 형태

- 콘텐츠 최대 너비: `1120px`
- 읽기 콘텐츠 최대 너비: `720px`
- 페이지 좌우 여백: 모바일 `20px`, 태블릿 `32px`, 데스크톱 `48px`
- 기본 간격 단위: `4px`; 주요 간격은 `8, 12, 16, 24, 32, 48, 64px`
- 카드 모서리: `24px`
- 버튼·입력 모서리: `16px`
- 캡슐 버튼: `999px`
- 기본 경계: `1px solid rgba(255,255,255,.12)`
- 그림자보다 배경 명도와 경계선으로 계층을 구분한다.

## 5. 핵심 컴포넌트

### Primary button

- 오렌지 배경, 흰색 Bold 텍스트
- 최소 높이 `52px`, 좌우 패딩 `20px`
- 한 영역에 하나만 배치

### Secondary button

- `grey-700` 배경, `grey-100` 텍스트, 12% 흰색 경계
- 문서 이동, 설정 안내처럼 되돌릴 수 있는 행동에 사용

### Support card

- `grey-800` 또는 `grey-700` 배경
- 제목, 1–3줄 설명, 선택적 링크 순서
- 카드 전체를 링크로 만들 때 목적을 명확한 텍스트로 표시

### Notice

- 일반 안내는 회색 정보 아이콘과 `grey-300`
- 안전·법적 주의는 빨강을 제목이나 아이콘에만 사용하고 본문 가독성을 유지

### FAQ

- 질문은 사용자가 실제로 입력할 표현으로 작성
- 한 답변은 핵심 결론 → 실행 방법 → 예외 순서
- 긴급 신고, 녹음, 위치, iCloud, 위젯을 최상위 범주로 둔다.

## 6. 서포트 페이지 정보 구조

1. Hero: “혼자 걷는 밤길도, 혼자가 아니도록” + 문의/FAQ CTA
2. 빠른 도움: 가상 통화, 위젯, SOS, 자동 녹음, iCloud
3. 자주 묻는 질문
4. 개인정보 및 데이터: 마이크·위치·녹음·iCloud 처리 방식
5. 문의: 지원 이메일, 앱 버전, iOS 버전, 문제 재현 단계
6. 긴급 안내: 즉각적인 위험 상황에서는 앱보다 112를 우선 사용

## 7. 문체

- 권장: “위젯을 누르면 바로 가상 통화를 시작할 수 있어요.”
- 비권장: “당사의 혁신적인 기능을 통해 통화를 실행하십시오.”
- 사용자를 겁주거나 안전을 보장하는 표현을 사용하지 않는다.
- “가짜 전화”보다 앱 내 표현과 일치하는 “가상 통화”를 사용한다.

## 8. 접근성

- 일반 텍스트와 배경은 WCAG AA 대비를 만족시킨다.
- 본문은 최소 `16px`, 터치 대상은 최소 `44×44px`로 한다.
- 색만으로 상태를 전달하지 않고 아이콘·레이블을 함께 제공한다.
- 키보드 포커스는 `2px` 오렌지 외곽선으로 명확히 표시한다.
- 모션 감소 설정을 존중하고, 자동 재생 영상은 사용하지 않는다.

구현용 CSS 토큰과 컴포넌트 미리보기는 같은 폴더의 `support-page-tokens.css`, `support-page-preview.html`을 사용한다.
